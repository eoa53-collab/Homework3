The design matrix X and response y need compatible shapes so there is one response for every row of the design matrix. The intercept column of ones allows the model to estimate a baseline outcome rather than forcing its fitted relationship through zero. Standardizing each predictor subtracts its mean and divides by its standard deviation, which puts predictors on comparable scales with means near zero and standard deviations near one. NumPy broadcasting applies the three-element vectors means and sds across every row of the predictor matrix without needing a separate Python loop.

X @ beta_hat performs matrix multiplication to calculate one fitted final score for every student. When the model includes an intercept, ordinary least squares makes the residuals sum to approximately zero, apart from small floating-point rounding differences. RMSE summarizes the typical size of the residuals in final-score units, with larger errors receiving extra weight because they are squared. X * beta_hat performs element-wise multiplication and returns a matrix of contributions, whereas X @ beta_hat combines those contributions into the fitted-value vector.

The check Q @ R ≈ X verifies that the QR factors reconstruct the original standardized design matrix. The check Q.T @ Q ≈ I verifies that the columns of Q are orthonormal. The SVD singular values describe the strength of the independent directions in X, and a singular value close to zero would suggest a weak or nearly redundant direction. A large condition number indicates that numerical calculations may be sensitive to small changes in the data. The following comparison shows whether standardization changes the condition number.

display(Markdown(

Part 5

Clean execution matters because another researcher should be able to recreate the report from the same source data and code without making extra corrections. When a report runs from the first line to the last line in a fresh session, it gives stronger evidence that the results do not depend on earlier experiments or forgotten commands. It also makes errors easier to find because each step has a clear place in the workflow.

Reusable code should not depend on hidden notebook state. For example, a variable created in a cell that was executed yesterday might still be in memory even if that cell was later removed. The notebook could appear to work for one person but fail when somebody else runs it from the beginning. In this homework, the data are loaded first, and every matrix is created from objects defined earlier in the same report.

For fitting the regression model, np.linalg.lstsq() is preferable to explicitly calculating (X.T @ X)^(-1) @ X.T @ y. Directly forming and inverting X.T @ X can make numerical problems worse, especially when predictors are closely related. The least-squares routine uses numerical methods designed to handle the calculation more reliably.

Floating-point operations also explain why np.allclose() is preferable to exact equality when checking QR and SVD reconstructions. Matrix factorizations involve many calculations that can introduce very small rounding differences. np.allclose() checks whether the results agree within an appropriate tolerance instead of demanding identical stored numbers.

The condition-number comparison taught me that the scale and centering of predictors can strongly affect numerical diagnostics. A raw design matrix may look poorly conditioned because columns use different units and ranges, while standardization can improve the numerical balance. However, standardization does not automatically solve true redundancy between predictors. One reproducibility practice I will carry into the final project is keeping the raw data unchanged and generating every result from ordered code using documented relative file paths.
